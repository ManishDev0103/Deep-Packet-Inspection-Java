# Phase 2 Plan 1: Switch to Java 21 LTS

## Objective

Make Java 21 LTS the current backend build/runtime requirement and verify the backend with a Java 21 JDK, preserving the Spring Boot 3.5.16 setup and existing behavior.

## Tasks

1. **Set the Java target** — Confirm `backend/pom.xml` uses `<java.version>21</java.version>` and retain the existing Spring Boot and WAR plugin versions unless verification establishes a blocker.
2. **Align runtime documentation and VS Code** — Update current Java 25 references in README, Windows setup instructions, and the JSP footer to Java 21. Leave historical Phase 1 artifacts unchanged. Configure `.vscode/settings.json` to use the user's selected local JDK 21 installation at `C:\Tools\jdk-21\jdk-21.0.10`.
3. **Verify on Java 21** — Set `JAVA_HOME` and `PATH` for the verification process to a JDK 21, confirm `java -version` and Maven's runtime version, run `mvn -f backend/pom.xml verify`, and require the WAR plus a nonempty Surefire report set with positive test count and zero failures/errors.
4. **Update tracking evidence** — Mark JRT-04/05/06 complete only after validation; update Phase 2 roadmap/state and add a phase summary and verification report. Preserve the completed Phase 1 Java 25 evidence as historical.

## Acceptance Criteria

- [ ] Maven compiler target is Java 21.
- [ ] Backend `verify` passes under Java 21 and produces the WAR.
- [ ] Existing backend tests are discovered and pass with no failures or errors.
- [ ] Current setup/product/footer text consistently identifies Java 21.
- [ ] VS Code selects the explicitly requested local JDK 21 path as its default JavaSE-21 runtime.
- [ ] Phase 2 tracking is complete and Phase 1 historical verification remains intact.
